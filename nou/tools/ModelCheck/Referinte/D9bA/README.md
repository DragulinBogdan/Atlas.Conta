# Cititorul A al originii partidei

SQL capturat din produsul anterior persistenței originii, după redenumirile
CLR, în `run-verificari/20261012-121930-504/d9b-f1/`. Fiecare JSON păstrează
comenzile în ordinea emiterii și parametrii lor cu `DbType`. Nu conține
șirul de conexiune. N/S: sistem/securizat; TOT/P50: integral/pagina50.

La pasul 6 al TR-D9b coloana `Latura` de pe `Postare` a devenit `Sens`:
în cele opt capturi REST și SOLDURI numele coloanei a fost înlocuit
(`p."Latura"` → `p."Sens"`, 24 de apariții), fără altă schimbare. Capturile
ORIGINI nu numeau coloana.

Acestea sunt artefacte de probă, fără referință din produs. Termenul B se
compară cu acest SQL rerulat pe aceeași bază și aceleași fapte ca B, după
producerea originilor prin scriitorul nou. Parametrii datei și utilizatorului
trebuie să identifice același context pentru ambele lecturi; cei capturați
aici sunt ai bazei private `.CodexD9bA`, scena PerfCub din ianuarie2065.

Raport, protocol și praguri: `docs/nucleu/tr-d9b-pas3-referinta.md` și
`docs/nucleu/tr-d9b-contract.md`, D9B-D7. SQL-ul A nu se regenerează din
cititorul B și nu devine ramură de compatibilitate în producție.
